# 拾光闲置 · 可用性设计与验收规范

更新：2026-10-12。适用范围：首页、详情、登录/注册、发布草稿、订单入口、全局帮助与反馈。

依据：[Nielsen Norman Group 十大可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)。以下是针对本平台的实现与验收规则，不等同于已完成用户研究或取得可用性认证。

## 页面结构

| 页面 | 信息顺序 | 核心操作 | 退出与恢复 |
| --- | --- | --- | --- |
| 首页 | 搜索/常用入口 → 分类/主视觉 → 兴趣频道 → 分类/排序/条件 → 商品 | 搜索、选择分类、价格排序、打开详情 | 移除单个条件、清除条件、撤销移除、保留滚动位置 |
| 详情 | 返回 → 商品图 → 标题/成色/价格 → 卖家/城市 → 商品说明 → 服务状态 | 核对商品信息 | 返回上一个列表及浏览位置；商品不存在时返回首页 |
| 登录/注册 | 返回 → 登录/注册切换 → 用途说明 → 带标签的字段 → 错误/状态 → 提交 | 登录后回到原任务；注册后登录 | 暂不登录；失败保留内容，直接重试 |
| 发布草稿 | 返回/状态 → 服务说明 → 进度 → 分类 → 描述 → 成色/价格/城市 → 操作 | 保存到本机、预览信息 | 取消；未保存离开提醒；清除前确认、清除后撤销 |
| 订单 | 返回 → 买入/卖出 → 服务状态 → 下一步 → 流程说明 | 选择买入或卖出记录视角 | 返回首页、准备发布草稿；Tab 通过 URL 保留 |

## 十项原则如何落地

| 原则 | 已实现行为 | 验收方式 |
| --- | --- | --- |
| 1 系统状态可见 | 请求中按钮 loading / 禁止重复提交，持久错误面板；图片真实加载骨架；结果数 aria-live；草稿保存/未保存状态 | 慢请求不重复提交；失败后可读；保存结果与实际存储一致 |
| 2 现实世界匹配 | 手机数码、服装鞋包、我买到的、我卖出的、保存草稿等直接名称；价格标明人民币元 | 首次使用者无需理解 API、业务码或内部名词 |
| 3 控制与自由 | 搜索 Escape 关闭；条件移除可撤销；草稿清除可撤销；离开可继续编辑；反馈本机保存可撤销 | 重复打开/关闭不困住用户；关键内容不因误点丢失 |
| 4 一致性与标准 | 统一主/次按钮、文字操作、状态提示、返回动作与字段标签；使用 Element Plus 对话框/表单 | 同一动作使用同一名称；对话框支持 Escape/焦点管理 |
| 5 防错 | 注册用户名格式、密码长度/确认；分类先于类型；价格大于 0 且两位小数；未开放交易/上传禁用 | 无效输入不能预览或提交；保存草稿允许不完整信息 |
| 6 识别优于回忆 | 最近六次搜索、热门搜索、已选条件标签、字段示例、草稿恢复、明确成色选项 | 返回或刷新后可辨识当前上下文；规则与字段同屏 |
| 7 效率与灵活性 | / 或 Ctrl/⌘+K 聚焦搜索；Enter 提交；分类/搜索/排序保存在 URL；价格排序 | 键盘可完成搜索；浏览器前进后退可恢复条件 |
| 8 审美与简约 | 暖白底、深色正文、克制红色动作；增大核心文字；减少装饰性英文；帮助渐进展开 | 正文清晰，主动作易辨认，手机无横向溢出 |
| 9 错误恢复 | 字段旁错误；登录失败面板说明并可重试；空搜索可以减少条件；存储失败保留输入 | 错误不只显示短暂 toast；失败不会伪装成功 |
| 10 帮助与文档 | 全局可关闭帮助抽屉；按当前页面呈现操作步骤；草稿/账号/交易说明就近出现 | 从任一页面能找到帮助，关闭后继续当前操作 |

## 可复用组件与样式

- AppHeader：输入、建议、历史记录、快捷键及常用导航。
- AccountForm：登录/注册共用字段、校验、loading、错误恢复，避免两页行为不一致。
- ProductVisual：真实图片 loading/成功/失败占位；不人为延迟本地数据。
- HelpPanel：按路由展示任务说明，使用 Element Plus Drawer 管理焦点与关闭。
- 全局样式：--accent、--surface、--text-secondary、--line；error-panel、availability-note、undo-bar、workspace-layout 等通用结构。
- preferences：存储损坏时安全读取；写入失败返回 false，草稿流程提供行动提示。

## 组件规则

1. 主要正文与操作文字 14–15px，辅助说明至少 12px；不能只用浅灰小字呈现关键限制。
2. 主要按钮/输入高度至少 44px；次要文本操作保留明确焦点与可点击范围。拥挤导航优先滚动，不截断主要动作。
3. 页面主按钮只推动当前任务：账号页登录/注册，发布草稿页保存。清除使用文字操作及确认，不与主动作同权重。
4. 错误同时包含对象、原因和行动：例如“草稿保存失败 → 检查浏览器存储设置 → 重新保存/复制内容”。保留已填内容。
5. 完成态必须准确命名：“保存至本机”不能称“发布成功”；“服务未开放”不能称“没有订单”。
6. 对真实异步等待展示状态；本地筛选即时更新，不增加假的加载延迟。图片失败切换占位，注册与登录失败保留可恢复路径。
7. 登录保留受保护页面的 redirect；注册与登录切换不丢失目标页面。前端守卫仍保留，不能为演示伪造登录。
8. 排序与筛选不跳到页面顶部；来自商品列表的详情返回使用浏览器历史，保留滚动。直接进入详情则回首页。
9. Undo 作用于最近一次本地操作：筛选移除、历史清空、草稿清除、反馈保存。服务器交易完成后的撤销需要独立业务契约，不假装可撤销。
10. 支持减少动画偏好、可见键盘焦点、跳至主内容、live 结果数与错误告警。颜色不是唯一状态标识。

## 当前能力与后续接口

首页和详情仍使用展示数据。注册/登录访问现有认证接口，能展示实际请求状态和失败恢复。发布仅保存当前用户在该浏览器的草稿，不上传照片、不创建商品。订单明确服务未开放，不显示虚构交易。反馈只保存到当前浏览器。

接入后端时：商品列表增加真实请求的 skeleton / 失败重试；发布增加上传进度、服务端校验与提交确认；订单增加真实状态、权限和幂等操作。应在 API 契约中定义哪些服务端操作可撤销，再提供对应操作。

## 已验证与后续研究

已通过自动浏览器检查：桌面/手机无横向溢出；搜索快捷键与历史；筛选清除/撤销；分类切换保留滚动；价格排序 URL；注册校验和失败内容保留；草稿保存/刷新恢复/离开保护/清除撤销；订单 Tab 与帮助。使用隔离测试浏览器验证受保护页面，没有更改用户实际登录态。

恢复专项检查通过：历史清空撤销、反馈保存撤销、图片失败占位、存储失败时草稿内容保留；停止登录等待后不产生登录态或迟到跳转，详情返回恢复分类与滚动。生产构建和现有 17 项单元测试通过。

仍需真实用户任务测试：让新用户找一件指定预算商品、恢复误清条件、准备草稿、解释交易是否已发生。记录完成率、误操作和理解偏差，再调整布局。当前行为符合启发式设计方向，不保证每位用户都零学习成本。
